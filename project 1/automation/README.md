# Linux Backup, Recovery and Triage

Bash scripts create timestamped compressed filesystem backups, verify SHA-256 before recovery, and collect basic host evidence. Requirements: Linux with Bash, GNU tar/coreutils, iproute2 and systemd for triage.

## Recovery exercise

From this directory in Bash:

```sh
mkdir -p /tmp/ops-example-source
printf 'recovery exercise\n' > /tmp/ops-example-source/sample.txt
archive=$(bash backup.sh /tmp/ops-example-source /tmp/ops-example-backups)
bash restore.sh "$archive" /tmp/ops-example-restored
diff -r /tmp/ops-example-source /tmp/ops-example-restored
```

Expected: checksum OK and no diff output. Restore refuses an existing destination. Repeat with a new destination path. Backup refuses a destination inside the source tree. Corrupt a COPY of an archive and confirm checksum validation prevents restoration.

Restore only trusted archives generated by the backup script. A checksum detects accidental corruption, not malicious replacement. Backups contain file data and must be stored with appropriate access controls. For a live database, use its native consistent dump or snapshot procedure before archiving. Retention, encryption and scheduled execution are intentionally left for the target environment.

## Initial incident triage

```sh
bash triage.sh > triage-report.txt
```

The report includes UTC time, load, memory, disk usage, listening ports and failed services. Review output before sharing because host details can be sensitive. Extend an incident record with impact, timeline, evidence, root cause, fix and a prevention action.
